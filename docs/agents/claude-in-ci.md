# Claude in CI

The automatic review runs for PR opens, updates, reopening and ready-for-review events. It checks out the event's head SHA, resolves a fixed diff, and reviews synchronously. A prior submitted Claude review with its run identity and merge-base markers supplies the incremental watermark only when its commit is an ancestor and the recorded merge-base matches the current one; uncertainty and repeat events use the full fixed diff. Runs for the same PR do not cancel an active review, although GitHub can replace a pending run.

A successful action alone is not evidence of a review. The job snapshots existing review IDs before the action and fails unless a new formal `<!-- astrology-claude-review -->` review with this run and attempt marker is submitted at the event SHA. A bot-owned status comment records scope, commit, outcome and run link; status updates are best effort. Inline findings appear under PR review comments. Review output depends on the action and classifier allowing the required API writes.

The deterministic controls run from the event base commit, rather than the checked-out PR head. The control script must exist on the base before this workflow can run. The action may skip execution when the workflow differs from the default branch. This PR therefore cannot prove the new workflow end to end: after merge, run it on a separate PR and confirm the marked review, inline findings when applicable, status comment, and failure behavior. Check both the run log and the review API.

The `@claude` workflow accepts mentions from owners, members and collaborators, subject also to the action's permissions check. It can make requested edits and use the action's push wrapper for the PR branch or a `claude/` issue branch. It is instructed not to merge or push main. Raw push and remote changes are denied. The action's app token and tag-mode tool grants are separate from the workflow token permissions; the branch restriction is an instruction, not server-side enforcement. The allow lists are narrow read fast paths; auto mode judges other actions, and deny rules provide additional but not complete protection.
