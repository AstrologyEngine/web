# Initial plugin wheel comparison

Captured 2026-11-07 in Chrome 157.0.8103.39, using the actual locally running plugin and website resolver and browser worker/Wasm calculations, with synthetic June 21, 2000 at 1:00 PM in London, England. Both used default Tropical, equal divisions and Whole Sign houses. Plugin source `498e21f61cde2f90760370fe826f27cc6d735d30`; website was the local #20 worktree in progress based on `c216e0e17ef784bd3e20b47b7f85720afa8c5192` (not a committed release).

Both captures use effective app widths of 1280px desktop and 390px mobile. At desktop the plugin and website wheel bounds were both 660×660px. At mobile the plugin wheel was 360×360px and website wheel 343.2×343.2px, reflecting the website's surrounding padding. Inspector app heights were 900px desktop and 663px mobile; website viewport heights were 900px and 844px. Plugin captures use a large outer Inspector window to avoid obscuring or clipping the wheel. These are wheel element captures, excluding host chrome.

Visual inspection: sectors, glyphs, positions, house boundaries, connectors, aspect lines and colors appear consistent at corresponding scale; both display the same dense placement pattern. The website wheel has a warm off-white surrounding surface versus the plugin's white surface. The plugin includes an upper-right enlargement control; the website slice has not yet added its later mobile navigation/interaction work. Mobile sizing differs as above. No unexplained numerical or geometry difference was observed in this single synthetic case; this is an initial visual check, not pixel-diff proof, an exhaustive fidelity pass, a deployed check, or beta acceptance. Interaction, mobile half-wheel and broader acceptance are later tickets.
